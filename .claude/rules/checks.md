# Проверки и запреты

## Запреты исполняемые, а не на словах

`.claude/settings.json` содержит `permissions.deny`. Это не рекомендации: агент физически не сможет
выполнить перечисленное.

| Запрет | Почему |
|---|---|
| `rm -rf`, `rm -r` | необратимое удаление; удаление — только поштучно и после проверки пути |
| `git push --force`, `-f` | переписывает чужую историю |
| `git add .`, `git add -A` | притаскивает `.env`, мусор, чужие файлы. Только поимённо |
| `git reset --hard`, `git clean -fd` | теряет незакоммиченную работу |
| `*DROP TABLE*`, `*DROP DATABASE*`, `*TRUNCATE TABLE*` | разрушение данных |
| `Read(./.env…)`, `Read(./server/config.php)` | секреты не читаются агентом даже для «проверить» |

**Ограничение честно:** шаблоны с `*` внутри (правила про SQL) — лучшая попытка, а не гарантия.
Синтаксис `Bash(команда:*)` — префиксное совпадение; сложные составные команды могут обойти шаблон.
Реальная защита данных — права пользователя БД и бэкапы, а не этот список.

**Если запрет мешает легитимной работе** — не обходить. Спросить и сделать вручную либо изменить
правило осознанно, отдельным коммитом с объяснением.

## Что проверять перед сдачей

```bash
npm run verify     # типы + сборка + контраст + скриншоты + структура
```

`verify` обязателен перед каждой сдачей. Смотреть скриншоты **глазами** — наличие файла не проверка.

Дополнительно руками:
- клавиатура: Tab по всей странице, фокус виден на любом фоне;
- `--reduce`: ничего не движется само;
- без JS: контент читается, ссылки работают;
- 320 px: ничего не липнет и не обрезается.

## Гейт перед выкладкой

```bash
npm run predeploy   # строгий: валит на TODO, плейсхолдерах, пустых реквизитах, битых ссылках
```

Деплой — только по явной команде. `predeploy` на чистом шаблоне падает намеренно: шаблон не деплоится.

## Приёмка чужой работы

Результат воркера принимается после машинной проверки, а не после слова «готово».
Читать дифф, а не отчёт. Если проверку выполнить нечем — это и есть вывод, а не повод пропустить шаг.
